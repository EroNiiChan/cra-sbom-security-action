# Security Policy & Vulnerability Disclosure

This project adheres to the cybersecurity and coordinated vulnerability disclosure requirements outlined in **Regulation (EU) 2024/2847 (European Cyber Resilience Act - CRA)**, specifically **Article 10(6)** and **Annex I Part II**.

---

## 🛡️ Supported Versions

We provide security updates and vulnerability patches for the following versions:

| Version | Supported | Status |
| :--- | :---: | :--- |
| `1.x` | ✅ Yes | Active Security Maintenance |
| `< 1.0` | ❌ No | Deprecated |

---

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability, credential exposure, or weakness in this tool or its SBOM parsing engine, please report it responsibly.

### 1. Private Vulnerability Reporting
Please **DO NOT** open a public issue. Instead:
- Use [GitHub Private Vulnerability Reporting](https://github.com/EroNiiChan/cra-sbom-security-action/security/advisories/new).
- Or email: `security@eroniichan.dev` (or reach out via GitHub profile).

### 2. Information to Include
Please include:
- Description of the vulnerability or secret detection bypass.
- Steps to reproduce or sample repository/manifest.
- Potential impact and suggested remediation.

### 3. Response & Notification Timelines (European CRA Standard)
In accordance with CRA Article 11 and Annex I requirements:
- **Initial Acknowledgment**: Within **24 hours** of receipt.
- **Triage & Assessment**: Within **72 hours**.
- **Fix & Advisory Release**: Coordinated patch delivery before public disclosure.
